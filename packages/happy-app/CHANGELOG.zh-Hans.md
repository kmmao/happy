## 2.34.0 - 2026-05-28

新增「应用锁」—— 可选的 PIN 码或生物识别门，让此设备上的应用内容保持私密。它是一个本地隐私防护：PIN 码仅控制此设备上对应用界面的访问，绝不触碰账户的端到端加密密钥。

### 应用锁
- 新增应用锁，在「设置 → 应用锁」中启用（仅移动端）：需要 6 位数字 PIN 码，可选 Face ID / Touch ID / 指纹解锁
- 新增可配置的重新锁定超时（立即 / 30 秒 / 1 分钟 / 5 分钟 / 从不）——「从不」表示应用在后台不会自动锁定，但冷启动仍需输入 PIN 码
- 新增手动「立即锁定」操作，可随时锁定应用
- 新增连续 5 次 PIN 码错误后的递增冷却（30 秒 → 1 分钟 → 5 分钟），不会擦除任何数据
- 新增「忘记 PIN 码？」路径：通过登出再重新登录来重置锁，没有任何后门
- 新增应用切换器遮罩：锁定时在最近应用预览中隐藏应用内容
- 改进隐私保护：仅在设备安全存储中保存 PIN 码的加盐 SHA-256 哈希；锁设置保留在设备本地，绝不同步

## 2.30.0 - 2026-05-22

后台任务管线的内部健壮性重构。本次发布无新功能——目标是让悬浮任务条注册表中的竞态条件和乱序 SDK 事件在开发期以抛错形式暴露，而不是默默让某个任务停留在错误的状态显示上。

### 后台任务稳定性
- 新增显式的 BackgroundTaskStatus 状态机（`running` → `completed` / `failed` / `stopped`,三个终态均为吸收态）——把生命周期定义集中到一处,不再散落在各处字符串比较里
- 改进 task-end 处理——任务注册表中的状态转换现在通过状态机校验,一次乱序的二次 `task-end` 事件无法再静默地把已结束的任务翻转到另一个终态
- 改进会话离线时正在运行任务的清理——"把陈旧任务标为 stopped" 路径现在在原有的 running-only 守卫之外,再叠加一层状态机校验作为保险
- 给 reducer 中那一处有意绕过校验的路径加了注释——`task-start` 晚于同任务的 `task-end` 到达是合法的 wire 级 SDK 乱序事件,不是 reducer 的 bug

### 代码整洁
- 删除子智能体状态助手中未使用的状态机 API——sub-agent 生命周期纯由底层 ToolCall 派生,没有可变存储,并行的容器/转换 API 在测试之外是 dead code；与后台任务之间的非对称性现已在源码注释中说明,供后续贡献者参考
